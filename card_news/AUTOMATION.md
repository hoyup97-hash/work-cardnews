# 카드뉴스 자동 발행 규칙

예약 작업(Claude)이 이 파일을 읽고 그대로 따릅니다. 규칙을 바꾸려면 이 파일만 고치면 됩니다.
동료의 카드뉴스 제작 프롬프트를 받으면 3~4번 항목에 반영하세요.

## 0. 범위
- 카드뉴스 HTML 1개를 만들어 커밋·푸시하고, 배포를 확인하고, 보고하는 것까지가 한 번의 실행입니다.
- 단톡방 발송 등 다른 곳에 메시지를 보내지 않습니다.
- 저장소: hoyup97-hash/work-cardnews (공개). main 에 푸시하면 GitHub Actions가 card_news/scripts/build.py 로 사이트를 만들어 https://hoyup97-hash.github.io/work-cardnews/ 에 배포합니다. 홈 화면은 가장 최근 카드(같은 날이면 번호가 큰 것)를 맨 위에 보여줍니다.

## 1. 파일 이름
- card_news/cards/YYYY-MM-DD.html (한국시간 오늘 날짜)
- 예약 지시문에 "같은 날 여러 개 허용"이 있으면: 이미 있으면 -2, -3 … 비어 있는 가장 작은 번호를 씁니다.
- 그런 말이 없으면: 오늘 날짜 파일이 이미 있으면(사람이 먼저 올린 것) 아무것도 바꾸지 말고 그 사실만 보고하고 끝냅니다.
- 이름 끝이 .html.html 인 파일도 같은 이름으로 칩니다. 기존 파일은 절대 덮어쓰거나 지우지 않습니다.

## 2. 템플릿
- card_news/cards/ 에서 가장 최근 파일(날짜·번호 기준, .html.html 포함)을 템플릿으로 씁니다.
- <head> 전체(스타일, base64 폰트), 하단 .nav 와 <script> 는 한 글자도 바꾸지 않습니다. <title>영업혁신실 신문</title> 유지.
- 바꾸는 것은 <section class="sheet"> 안의 텍스트·링크뿐. 구조 고정: 1 = 1면(헤드라인 3개), 2~4 = 기사별 3줄 요약, 5 = "이 기사들도 읽어보세요!" + 일정.
- 날짜(dateline, 각 장 mast 오른쪽)는 오늘 날짜 "11월 6일(금)" 형식. 출처 옆 날짜는 기사 게재일 "보험저널 11.05". 마지막 장 foot 오른쪽은 "MM.DD HH:MM 기준 · 원문 요약"(실행 기준 시각).

## 3. 기사 조사 (WebSearch·WebFetch)
- 실행 시각까지 나온 국내 보험 업계 기사. 오늘자 우선, 부족하면 전날 오후 이후.
- 생명보험 영업·판매채널 중심. 우선순위: GA(법인보험대리점), FP(전속설계사), BA(방카슈랑스), TM(텔레마케팅), 판매수수료·분급·1200%룰 등 판매 제도, 금융당국 규제, 경쟁사 영업전략·상품.
- 주요 출처: 보험저널(insjournal.co.kr), 보험매일(fins.co.kr), 보험신보, 한국보험신문, 대한금융신문, 그 밖의 경제지. 원문 페이지를 직접 열어 확인한 기사만 씁니다.
- 같은 날 앞서 올라간 카드가 있으면 열어 보고 가능하면 겹치지 않는 기사를 고릅니다.
- 1면 헤드라인 3개 = 2~4번 장 기사 3개(영업 현장 영향이 큰 순서). 관련 기사 2~4개는 5번 장에.
- 기사에 나온 확정 일정은 5번 장 일정 줄에. 날짜가 불명확하면 빼거나 보고에 "확인 필요"로 적고, 일정이 없으면 그 줄을 지웁니다.
- 관련 기사가 2개 미만이면 만들지 말고 이유만 보고합니다.

## 4. 작성 규칙
- 1면 헤드라인마다 핵심 어구 하나에 <span class="circ">(숫자·비율)</span> 또는 <span class="ul">(핵심 어구)</span>.
- 3줄 요약은 기사 문장을 베끼지 말고 직접 요약. 각 줄 1~2문장, "~함/~임" 말투, 대략 90자 이내. 기사에 없는 해석·예측 금지.
- 태그(.tag) 2개: 채널(GA/FP/BA/TM) + 주제(영업전략/제도/상품/실적 등). 출처(.src) "언론사 MM.DD". 원문 보기 = 실제 기사 URL.
- 1면 foot 왼쪽 "GA n · FP n · BA n · TM n" = 이번 카드(2~5번 장)에 실린 기사를 채널별로 센 개수.
- 회사명·인물·숫자는 기사 표기와 정확히 같게.

## 5. 검증 (커밋 전에 반드시)
- 각 원문을 다시 열어 요약 속 숫자·고유명사·날짜 대조, 틀리면 수정. 모든 링크가 실제 기사로 열리는지 확인.
- section 5개, 템플릿과 같은 head/script 인지 확인.
- 저장소 루트에서 python3 card_news/scripts/build.py 실행해 오류 없는지 확인 후 card_news/_site 삭제(커밋 금지).

## 6. 커밋·푸시
- 새 카드 파일 하나만 추가. 다른 파일 수정·삭제 금지.
- 커밋 메시지 "M/D HH:MM 카드뉴스 자동 생성" (시험이면 끝에 "(시험)"). main 에 푸시. 거절되면 git pull --rebase 후 다시 푸시.
- 2~3분 뒤 https://hoyup97-hash.github.io/work-cardnews/manifest.json?t=현재시각 에서 방금 올린 파일이 맨 위인지 확인.
